\begin{frame}{Summary}
\small
\begin{enumerate}\small
  \item \textbf{Ran every Tricycle matrix multiplication encrypted on a GPU} through Cerium, at three layer sizes. All outputs correct.
  \item \textbf{Ran and profiled the baseline:} Cerium's own encrypted BERT-Base, end to end.
  \item \textbf{Found why Tricycle's weight multiplications were slow:} a Cerium compiler setting, not the algorithm.
  \item \textbf{Cut our matrix-multiplication time} for one BERT-Base layer from 2.81 s to 0.20 s.
\end{enumerate}
\vspace{0.6em}
\begin{block}{Headline}
Every Tricycle matrix multiplication is now faster than Cerium's own: 4.6$\times$ faster per layer in total (2.2$\times$ for QKV up to 8.2$\times$ for attention).
\end{block}
\end{frame}

\begin{frame}{Result 3: why Tricycle's weight multiplications were slow}
\small
Profiling Tricycle's QKV (BERT-Base, one layer) with Nsight Systems:
\begin{center}\footnotesize
\begin{tabular}{@{}lrrr@{}}
\toprule
\textbf{Kernel time} & \textbf{Key switching} & \textbf{Plaintext multiply-accumulate} & \textbf{Total}\\
\midrule
Cerium's default fusion block size (1024) & 28 ms & 923 ms & 951 ms\\
Block size 32 (what Cerium's BERT uses) & 16 ms & 90 ms & 106 ms\\
\bottomrule
\end{tabular}
\end{center}
\begin{itemize}\small
  \item Rotations were never the problem. The time was in the element-wise multiply-accumulate kernels.
  \item With block size 1024 those kernels reached about 3\% of the GPU's memory bandwidth.
  \item Cerium's BERT sets block size 32 for its weight multiplications; our programs had the default. Same change, about 10$\times$ less multiply-accumulate time.
  \item Earlier guesses (compressed plaintexts, fused rotations) were not the cause. Compressed plaintexts cannot work with Tricycle's encoding anyway.
\end{itemize}
\end{frame}

\begin{frame}{Takeaways and next steps}
\small
\begin{block}{Takeaways}
\begin{itemize}\small
  \item All Tricycle matrix multiplications run correctly, encrypted, through Cerium, and each one beats Cerium's.
  \item Compiler settings matter as much as the algorithm: one setting was worth 9$\times$.
  \item Bootstrapping is half of Cerium's BERT time. Swapping in Tricycle's matrix multiplications alone would make a Cerium layer about 1.4$\times$ faster (3.16 s to 2.28 s).
\end{itemize}
\end{block}
\begin{block}{Next}
\begin{itemize}\small
  \item One complete encrypted Tricycle layer: add softmax, GELU, LayerNorm and bootstrapping, then compare end to end with Cerium's 3.16 s per layer.
  \item Fairness check: whether Cerium's own BERT matmuls also speed up under other compiler settings.
\end{itemize}
\end{block}
\end{frame}
